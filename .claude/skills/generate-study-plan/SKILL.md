# Генерация учебного плана

Создаёт в папке темы учебный план (`plan.md`) и контрольные вопросы (`tests.md`).
Запускается, только если в папке темы **нет** `plan.md`. Если план есть, скилл не нужен:
обучение продолжается по нему (см. `CLAUDE.md`, раздел «Обучение»).

## Входные данные

- Папка темы в `workspace/` (уже разобранная по правилам `CLAUDE.md`).
- Файлы ребёнка в ней: вопрос, картинки из учебника, PDF — что угодно.
- **Сгенерированные файлы входными данными не являются** (см. «Метка» ниже).

## Шаги

### 1. Понять тему

Прочитай все файлы ребёнка в папке темы (картинки и PDF тоже). Определи тему, её объём
и что именно ребёнок хочет выучить. Если непонятно — спроси ребёнка.

### 2. Поискать в `materials/`

Посмотри `materials/INDEX.md` (при необходимости сами файлы): тематические планы школы,
учебники, рабочие листы по теме. Используй найденное как основу, чтобы попасть в школьную
программу и её терминологию.

### 3. Собрать материал

- Язык — язык занятий из профиля ребёнка (`child_info/profile.md`).
- Материал **исчерпывающий** по теме, с учётом возраста и класса ребёнка из профиля.
- **Фундаментальные темы**, в которых модель хорошо обучена: используй собственные знания.
- **Если нужно уточнить или дополнить** — ищи в интернете.

**Ограничения на источники:**

- **Запрещено** использовать учебные материалы стран с коммунистическим, тоталитарным
  или диктаторским режимом.
- **Никакой конспирологии.** Только проверенные факты.
- Источники — только надёжные ресурсы демократических стран.
- Использованные внешние источники перечисли в `plan.md`.

### 4. Разбить на блоки

Раздели материал на **маленькие блоки**: один блок — одна мысль/понятие/приём, который
можно объяснить и проверить за несколько минут диалога. Блоки идут от простого к сложному.
В каждом блоке: объяснение, примеры, при необходимости разобранная задача.

### 5. Контрольные вопросы

Для **каждого** блока составь несколько (3–5) контрольных вопросов с правильными ответами.
Вопросы должны проверять понимание, а не только запоминание формулировок.

### 6. Сохранить

В папку темы запиши два файла, оба с меткой в первой строке.

**`plan.md`:**

```markdown
<!-- learning-pipeline: generated -->
# <Тема>

- Дата создания: ГГГГ-ММ-ДД
- Язык: <язык занятий>
- Входные файлы: <список файлов ребёнка>
- Источники: <materials/…, внешние ссылки>

## Прогресс

- [ ] Блок 1: <название>
- [ ] Блок 2: <название>
- …
- [ ] Контрольные вопросы по блокам
- [ ] Финальный блиц-тест (≥ 90 %)

## Журнал

<!-- дата — что прошли, где остановились, что вызвало трудности -->

## Блок 1: <название>

<материал блока>

## Блок 2: <название>

…
```

**`tests.md`:**

```markdown
<!-- learning-pipeline: generated -->
# <Тема> — контрольные вопросы

## Блок 1: <название>

1. <вопрос>
   - Ответ: <правильный ответ>
…
```

Финальный блиц-тест здесь **не** генерируется: его составляют в момент тестирования
(см. `CLAUDE.md`, раздел «Обучение»).

### 7. Начать обучение

После сохранения переходи к обучению по `CLAUDE.md`, начиная с блока 1.

## Метка

Все сгенерированные файлы начинаются со строки:

```markdown
<!-- learning-pipeline: generated -->
```

Файлы с этой меткой (а также `plan.md`, `tests.md`, `final-test-*.md`) никогда не считаются
входными данными ребёнка, даже если он пришлёт их вместе с новыми вопросами.
